# Implementation Notes: Интеграция со Slack / Mattermost

Этот файл предназначен для документирования архитектурных и кодовых изменений, внесенных в исходную систему `msgsender` для обеспечения работы уведомлений в Slack. Информация ниже будет полезна при код-ревью и разработке новых типов интеграций (например, с MS Teams или Discord).

## Скрипты обработки (Scripts & Routing)

* **Скрипт `/bin/slack`:** 
  Был создан скрипт `msgsender/bin/slack`, который выступает точкой входа (обработчиком) для формирования Slack-уведомлений со стороны ядра `msgsender`. 
  
  **Ключевая логика и функции:**
  * `setup_environment(lang)`: Инициализирует окружение `Jinja2` (через `FileSystemLoader`) и подключает расширения `jinja2.ext.i18n` и `jinja2.ext.do`. Загружает нужные файлы переводов с помощью `gettext.translation` на основе языка пользователя.
  * Класс `Message.render()`: Получает контекстные переменные из `stdin` и рендерит итоговый текст уведомления, подставляя локализованные строки.
  * `parse_params(params)`: Извлекает из JSON-полезной нагрузки поле `webhook_url` (в отличие от `chat_id` у Telegram) и передает параметры в шаблонизатор.
  * **Сетевое взаимодействие:** Скрипт формирует POST-запрос с телом `{"webhook": webhook_url, "text": message}` к микросервису `slack-srv` на эндпоинт `/sendMsg`.

  **Главные отличия от `/bin/telegram`:**
  1. Работа с **Webhooks**: В качестве адресата скрипт ожидает и извлекает URL вебхука (`webhook_url`), тогда как Telegram оперирует `chat_id`.
  2. Формат Payload: В `slack-srv` улетает `{"webhook": ..., "text": ...}`, а в Telegram улетало `{"chat": ..., "msg": ...}`.
  3. **Обработка HTTP 202**: Slack-скрипт считает успешной доставку не только при коде `200`, но и при коде `202 (Accepted)`. Это связано с тем, что `slack-srv` может брать сообщения в асинхронную очередь при Rate Limits от Slack, возвращая `202`. В Telegram-скрипте ожидался строго `200`.

## Изменение скриптов синхронизации

Существующие скрипты синхронизации каналов и пользователей были модифицированы для поддержки Slack по аналогии с Telegram:

* **В `msgsender/bin/channel_syncer.py`:**
  * Добавлена функция `get_msgs_slack_channels()`, которая получает список Slack-каналов через вызов API `msgsender` (`channel?where=delivery_method+EQ+'slack'`).
  * Изменена функция `sync_channels()`. Теперь она помимо `telegram_channels` парсит массив `slack_channels` из словаря `channels_in_settings`. Если канал отсутствует в `msgs_slack_channels`, он удаляется из настроек с последующим вызовом API `alert_client.post("setting/{setting_id}")`.
  * Функция `settings_delete_channel()` адаптирована для работы с динамическим параметром `delivery_method` (ранее жестко удаляла только из массива `telegram`). Теперь в обработчике события `on_channel_delete` метод доставки определяется динамически: `notification.get("data", {}).get("delivery_method", "telegram")`.

* **В `msgsender/bin/user_syncer.py`:**
  * Аналогично `channel_syncer.py` добавлена базовая обработка сущностей пользователей для Slack.

*(Примечание: На текущем этапе функционал маппинга и синхронизации для Slack только заложен в код, но полностью не протестирован в боевых условиях).*

## Шаблоны и Локализация

Для формирования текстов уведомлений была добавлена новая структура шаблонов:

* **Добавление шаблонов Slack:**
  Созданы новые директории и файлы разметки (в основном `.mf` и `.jinja`) по пути `msgsender/etc/templateзаглушка для ссылки на документацию по slack-srv/dci/slack/` (для инфраструктуры DCI) и `msgsender/etc/template/vm/slack/` (для инфраструктуры VM).
  > **Почему не переиспользовали шаблоны Telegram?** Slack и Telegram используют разные диалекты Markdown. Например, в Telegram ссылки оформляются как `[текст](url)`, а в Slack используется собственный формат `mrkdwn`, где ссылки выглядят как `<url|текст>`. Также есть различия в экранировании спецсимволов и блоках кода. Из-за этого пришлось адаптировать верстку и выносить Slack-шаблоны в отдельные директории.
* **Локализация:**
  Тексты внутри шаблонов оборачиваются в функции `gettext`. Используются общие PO/MO файлы из директории `locale` для перевода на русский, английский и испанский языки.

## Метаданные (Metadata)

* **Изменение `metadata.json`:** 
  В файл `msgsender/etc/template/metadata.json` (основной реестр конфигураций уведомлений) были добавлены блоки конфигурации для метода доставки `slack`.
  Например, добавлены блоки с ключом `"delivery_method": "slack"`, которые указывают ядру `msgsender`, какой именно файл шаблона (`params.body`) использовать для конкретного языка (например, `dci/slack/alert_dss_chassis.mf`).

## Микросервис slack-srv

* Для изоляции логики отправки и соблюдения лимитов Slack API (Rate Limits / Retry-After) был разработан новый асинхронный сервис `slack-srv` (на базе `aiohttp`).
* Решение о вынесении логики в микросервис принято по аналогии с существующим `telegram-srv`. Это позволяет не блокировать работу основного контура `msgsender` при сетевых задержках со стороны мессенджера.
* Документация по микросервису располагается в его репозитории (заглушка для ссылки на документацию по slack-srv).
