# Документация по тестированию интеграции со Slack (msgsender-slack)

В данном документе описан подход к тестированию контура отправки сообщений в Slack/Mattermost, основные сценарии (тест-кейсы) и инструкции по запуску и масштабированию тестов.

## Общая логика тестирования

Тестирование интеграции `msgsender-slack` проводится с использованием интерактивного Python-скрипта (`msgsender/test_slack.py`). Скрипт не использует моки для сетевых запросов и проверяет работу всей связки "msgsender-скрипт (`bin/slack`) -> микросервис (`slack-srv`) -> конечный мессенджер (Webhook)" (End-to-End подход). 

Тестирование логически разделено на два блока:
1. **Проверка доставки сообщений (Блок 1):** Запуск бинарника `bin/slack` через `subprocess` для валидации правильной передачи данных и маршрутизации запросов в микросервис.
2. **Проверка рендеринга шаблонов (Блок 2):** Динамическая загрузка скрипта отправки и рендеринг всех доступных шаблонов `.mf` (Jinja2) на разных языках, а также визуальная (E2E) отправка отрендеренного результата в тестовый канал для проверки форматирования.

## Тест-кейсы и их "бизнес"-значимость

### Блок 1: Проверка доставки сообщений (через slack-srv)

Данный блок закрывает риски, связанные с потерей сообщений из-за неполных данных и проверяет отказоустойчивость контура при высоких нагрузках.

*   **Успешная доставка с полным набором полей**
    *   **Бизнес-значимость:** Гарантирует работоспособность основного "счастливого пути" (Happy Path). Проверяет, что система корректно обрабатывает все передаваемые сущности (product, version, env).
*   **Доставка с частичным или минимальным набором полей (только язык)**
    *   **Бизнес-значимость:** Закрывает риск падения скрипта при отсутствии необязательных полей. Гарантирует, что при частичной деградации системы мониторинга нотификация все равно будет доставлена адресату.
*   **Проверка Rate Limiting (быстрая отправка сообщений)**
    *   **Бизнес-значимость:** Slack/Mattermost имеет строгие лимиты на частоту запросов (например, 1 сообщение в секунду). Этот тест отправляет серию сообщений без пауз, гарантируя, что `slack-srv` корректно обрабатывает HTTP 429 и ставит сообщения в очередь с ретраями, в то время как основной контур `msgsender` завершается без ошибок.

### Блок 2: Проверка рендеринга шаблонов Jinja2

Данный блок закрывает риски отправки нечитаемых, некрасивых или технически невалидных сообщений (сломанная разметка, битые переменные) в чаты пользователей.

*   **Рендеринг шаблонов для всех языков (en, ru, es)**
    *   **Бизнес-значимость:** Проверяет отсутствие синтаксических ошибок в шаблонах для всех поддерживаемых локализаций. Обеспечивает уверенность, что изменение базовых параметров макросов не сломает отправку уведомлений.
*   **E2E визуализация (отправка отрендеренного RU шаблона)**
    *   **Бизнес-значимость:** Позволяет инженеру или QA своими глазами увидеть итоговый результат в Slack. Удостоверяет, что верстка (блоки, цвета) выглядит так, как задумано, и что все мок-переменные успешно подставились в текст.

## Инструкции для разработчиков (Масштабируемость)

Скрипт поддерживает как интерактивный запуск с выбором нужных блоков через меню, так и запуск с аргументами командной строки для автоматизации в CI/CD.

### Зависимости

Скрипт требует Python 3.10+ и следующие зависимости:
*   `jinja2`
*   `requests`

### Локальный запуск (рекомендуемый способ)

Для локального запуска вне докера можно использовать пакетный менеджер `uv`. Если микросервис запущен локально, он будет доступен на `localhost:8080`:

```bash
uv run msgsender/test_slack.py
```
*Скрипт автоматически скачает нужные зависимости и запустит интерактивное меню.*

### Запуск внутри Docker

Основной сценарий при развернутом окружении. В этом случае скрипт обращается к микросервису по внутреннему имени `slack-srv:8080`.

```bash
docker exec -it dev-msgsender python3 /opt/ispsystem/msgsender/test_slack.py
```

**Примеры неинтерактивного запуска с аргументами:**
*   Только доставка: `docker exec -it dev-msgsender python3 /opt/ispsystem/msgsender/test_slack.py --delivery --webhook https://...`
*   Только шаблоны: `docker exec -it dev-msgsender python3 /opt/ispsystem/msgsender/test_slack.py --check-templates --webhook https://...`
*   Все блоки: `docker exec -it dev-msgsender python3 /opt/ispsystem/msgsender/test_slack.py --all --webhook https://...`

### Добавление новых проверок в будущем

1.  **Для проверки логики маршрутизации (новых форматов payload):**
    Добавьте новый вызов `_delivery_case()` в функцию `run_delivery_tests(webhook_url)` с необходимым JSON payload внутри файла `test_slack.py`.
2.  **Для тестирования новых шаблонов:**
    Если вы создали новый файл шаблона в директории `etc/template/slack/` с расширением `.mf`, скрипт **автоматически** найдет его и протестирует благодаря рекурсивному поиску (`TEMPLATES_PATH.rglob("slack/*.mf")`). Изменения в коде тестов не требуются.
3.  **Для добавления новых мок-данных в шаблоны:**
    Если новый шаблон требует параметров, которых еще нет в тестах, добавьте эти мок-данные в глобальный словарь `UNIVERSAL_MOCK_PARAMS` в файле `test_slack.py`.
